## Security fixes in 0.1.2

Admin-key capabilities no longer authorize changes to super-admin profiles,
email addresses, attributes, memberships, sessions, or owned API keys. This
closes an account-takeover path through changing a super-admin's email and then
requesting password recovery. Affected requests return HTTP 403 before mutation.

Organization updates/deletion involving super-admin members are also protected.
First-party OAuth clients trusted by the admin API require a super-admin for
creation and mutation, including promotion of another client to first-party.

Super-admin Console/session users keep their account-management operations.
Normal-user automation retains its capability-based behavior. No schema
migration or credential rotation is required; upgrade all replicas before
relying on these protections. See
[admin-key permissions](https://github.com/alessioforte/stargate/blob/v0.1.2/docs/admin-keys.md).
